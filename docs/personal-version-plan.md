# 自用精简版实施记录

用户要求：只保留浅色主题，去掉落地页、AI 及多余页面，以批量管理、排序、查看收藏为中心，并直接更新线上站点。

采用现有 Next.js / SQLite / GitHub 登录，不重写认证或改动现有个人数据。首页进入收藏库，未登录进入简洁登录页。导航只保留收藏库和分类标签管理。原 AI、推荐、贡献等页面和接口停止提供服务。保留源码中不再被页面引用的通用组件，避免无关删除影响升级。

收藏库保留用户认可的原项目卡片作为默认视图，并可切换紧凑表格。继续展示项目主要信息，支持搜索、语言/归档/重点/分类/标签筛选，收藏时间、推送时间、创建/更新时间、Stars、Forks、名称双向排序；未知时间置后，排序后分页。分页可跨页勾选，可选当前页或当前筛选全部，筛选改变清空选择。详情侧栏仅显示仓库信息、README、备注及本地分类。

批量操作：添加/移除标签和分类、设置/取消重点、导出、取消收藏。取消收藏先确认完整清单并保存数据库快照，后台串行执行，页面展示进度与暂停/继续/取消/失败重试；不自动取消任何真实收藏。测试只使用模拟 GitHub。

实施顺序：

1. 回归用例：双向排序/NULL/分页选择/全量同步超 5000、批量归属校验和原子性、取消收藏错误与重启对账。
2. 数据字段增量迁移及批量接口/持久化执行，保持原标签备注兼容。
3. 精简入口、主题、导航、收藏库、详情及分类标签设置，移除 AI 路由。
4. 类型检查、Lint、既有检查及新增检查；隔离环境的桌面/手机页面验证。
5. 备份生产 SQLite，构建固定版本镜像，更换容器复用原数据卷，检查 HTTPS、登录、接口鉴权、资源及持久化。
