# 服务器执行资源硬约束

用户明确要求（2026-11-26）：构建和测试允许慢一点，但不允许把系统资源占满，系统资源占用最多只允许 90%。这条要求适用于之后在此服务器执行的工作。

用户追加上限：我启动的构建、测试等任务合计最多使用 2 核 CPU、2 GB 内存；这不是必须用满的配额，仍须满足整机 90% 限制，并按余量降低实际配额。

1. 按整机 CPU 和内存占用计算 90% 上限，不能只看当前容器或 Node 堆。内存使用 MemAvailable 判断，并关注交换区和 I/O 等待。
2. 开始前检查资源余量，重任务串行执行。为构建和测试设置 CPU、内存硬限制，不与浏览器测试并行。单独设置 NODE_OPTIONS 并不能限制整个构建的占用。
3. 执行过程中持续监控整机，提前在 80%~85% 停止本次任务，给系统和其他服务留出缓冲；不能等到卡顿后才处理。
4. 优先复用已有缓存，允许增加完成时间。资源不足时不得启动不受限的 Docker 全量构建，也不得为腾出资源停掉其他项目。
5. 停止任务后核对进程已经退出、线上站点仍健康。未完成的发布必须明确标记待完成，不能声称已上线。

这份文件和部署清单用于持久保存用户要求，不代表已修改平台系统级指令。
